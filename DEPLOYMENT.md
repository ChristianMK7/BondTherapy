# Deploying Bond Therapy

Bond Therapy is a **stateful Node/Express server**: it runs a long-lived process,
stores data in a local SQLite file (`data/bond.db`), saves uploaded files to
`uploads/`, keeps login sessions in memory, and runs a daily backup timer.

That rules out **serverless** hosts. **Vercel and Netlify will not work** — they
run short-lived functions with no persistent process or writable disk. Use a host
that runs a real Node service: **Render** (easiest) or **Fly.io** (persists data).

---

## Run locally first

Requires **Node 18+** (20 recommended).

```bash
git checkout main
git pull origin main
npm install
cp .env.example .env      # then edit the values
npm start                 # http://localhost:3000
```

- Main site: `http://localhost:3000/`
- Therapist application: `/therapist`
- Admin panel: `/admin` (or log in on the main site with the admin username)
- Therapist portal: `/therapist-portal`

To wipe the local database and start clean: `npm run reset-db`.

## Option A — Render (recommended for a quick client demo)

A `render.yaml` blueprint is included, so most settings are filled in for you.

1. Push this repo to GitHub (already done).
2. In Render: **New +** → **Blueprint** → pick the `BondTherapy` repo → **Apply**.
   (Or **New +** → **Web Service** and set Build = `npm install`, Start = `npm start`.)
3. Set the environment variables (the blueprint generates `SESSION_SECRET` for you):

   | Variable | Value |
   |----------|-------|
   | `NODE_ENV` | `production` |
   | `SESSION_SECRET` | auto-generated by the blueprint (or any long random string) |
   | `ADMIN_USER` | `admin` |
   | `ADMIN_PASS` | **a strong password you choose** — required, the app refuses to boot without it |

   Optional (only if you want them): `PLATFORM_FEE_PERCENT`, `WHISH_NUMBER`,
   `WHISH_NAME`, `OMT_NUMBER`, `OMT_NAME`, `CONTACT_*`, and the email vars
   `RESEND_API_KEY` / `EMAIL_FROM` / `EMAIL_ADMIN` for notification emails.
   You do **not** need to set `PUBLIC_URL` — Render injects `RENDER_EXTERNAL_URL`
   and the app uses it automatically.

4. Deploy. Render gives you a URL like `https://bond-therapy.onrender.com` — send
   that to your client.

### ⚠️ Free-tier caveats (important for the client test)
- **Data is ephemeral.** The free disk resets on every deploy and after the
  service spins down when idle (~15 min no traffic). Therapists, bookings and
  uploads created during testing **will not survive** a restart.
- **Cold starts.** A spun-down free service takes ~30–60s to wake on the first
  request. The client may see a slow first load.

If the client needs data to persist across days, either:
- upgrade the Render service to a paid plan and attach a **disk** mounted at
  `/opt/render/project/src/data` (this is where `bond.db` and backups live), or
- use Fly.io below (free volume).

## Option B — Fly.io (free, persists SQLite data)

Better if you want created data to stick around. Requires the `flyctl` CLI.

```bash
# install flyctl: https://fly.io/docs/flyctl/install/
fly launch --no-deploy            # generates fly.toml; pick a name/region
fly volume create bond_data --size 1   # 1 GB persistent volume
```

Then in `fly.toml` mount the volume and set the data dir:

```toml
[[mounts]]
  source = "bond_data"
  destination = "/data"

[env]
  NODE_ENV = "production"
  DATA_DIR = "/data"            # see note below
```

Set secrets and deploy:

```bash
fly secrets set SESSION_SECRET="$(openssl rand -hex 32)" ADMIN_PASS="your-strong-pass"
fly deploy
```

> Note: the server currently hard-codes its data directory to `./data`. To use a
> Fly volume mounted at `/data`, change `DATA_DIR` in `server.js` to read
> `process.env.DATA_DIR || path.join(ROOT, 'data')`. Tell me and I'll make that
> one-line change.

## Environment variables reference

See `.env.example` for the full annotated list. The only **required** ones in
production are `SESSION_SECRET` and `ADMIN_PASS` — the server intentionally
refuses to start without them so you never ship default credentials.

## Before a real public launch (not just a demo)
- Replace the demo `ADMIN_PASS` with a strong, unique password.
- Have the Privacy Policy and Terms reviewed by qualified legal counsel.
- Configure Resend (`RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_ADMIN`) so booking,
  application and password-reset emails actually send.
- Move to a host/plan with a **persistent disk** so data is not lost.
